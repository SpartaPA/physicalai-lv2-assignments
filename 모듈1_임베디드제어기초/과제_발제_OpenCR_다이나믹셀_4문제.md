# Lv.2 모듈 1 과제 발제: OpenCR·다이나믹셀

## 과제 안내

OpenCR과 다이나믹셀 1개를 사용해 목표값을 보내고, 측정값을 읽고, 제어 설정에 따른 차이를 확인합니다. 이론 1~4강과 실습 5~8강을 두 강씩 연결한 **통합 문제 4개**입니다. 기존 모듈 1 과제를 대체하는 축소 개정본입니다.

**발제 멘트:** “새로운 제어 프로그램을 처음부터 만드는 과제가 아닙니다. 수업에서 사용한 예제를 실행하고, 로그를 읽고, 설정 하나를 바꿔 결과를 설명하면 됩니다. 가장 빠르거나 정확한 모터를 만드는 것보다 내가 보낸 명령과 실제 움직임을 연결해 설명하는 것이 목표입니다.”

- 대상 장비: OpenCR 1.0, 다이나믹셀 1개, 해당 모델에 맞는 전원과 통신 케이블.
- 예상 시간: 환경 준비가 끝난 상태에서 실습·답안 작성 약 90분. 장비 대기와 최초 설치 시간은 별도입니다.
- 제출 방식: 개인 보고서 2쪽 이내. 장비를 함께 사용한 경우 공동 측정자를 적고 해석은 각자 작성합니다.
- 사용 코드: 수업에서 제공한 예제를 그대로 사용해도 됩니다. 새 펌웨어·ROS2 패키지 작성은 요구하지 않습니다.
- 제출일: 수업 운영 공지에 따릅니다.

| 문제 | 연결하는 강의 | 핵심 작업 | 예상 시간 | 배점 |
|---|---|---|---|---|
| 1. 명령과 움직임 확인 | 1강 제어 응답 + 5강 액추에이터 구동 | 목표 1회 입력, 응답 확인 | 15분 | 25점 |
| 2. 센서값과 피드백 해석 | 2강 피드백 + 6강 센서 인터페이스 | 같은 로그에서 측정값·오차 읽기 | 20분 | 25점 |
| 3. 제어 설정 비교 | 3강 PID + 7강 목표값 추종 | P 게인만 바꿔 2회 비교 | 30분 | 25점 |
| 4. 제어 주기와 통신 구분 | 4강 MCU·타이머 + 8강 ROS2 연동 | 제공된 통신 기록과 구조 해석 | 15분 | 25점 |

나머지 10분은 답안과 제출물 정리에 사용합니다. 문제 1의 실행을 문제 3의 첫 번째 실행으로 재사용할 수 있습니다.

## 시작 전 확인

진행자는 수업 전에 모터 모델, TTL/RS-485 연결, 전원, ID, 통신속도, 운전 모드를 확인하고 동작이 검증된 예제를 배포합니다. 학생은 배포된 설정표를 보고 실제 장비와 일치하는지 확인합니다.

현재 저장소의 `opencr_position_p` 예제는 **XM430-W350, 모델 번호 1020**을 기준으로 작성되어 있습니다. 다른 다이나믹셀이라면 진행자가 호환되는 예제를 준비해야 합니다. 모델 검사만 지워 실행하지 않습니다. 과제 자체가 특정 모델 구매를 요구하는 것은 아닙니다.

이 예제에서는 OpenCR이 위치 오차로 목표 속도를 계산하고, 다이나믹셀에는 속도 명령을 보냅니다. 모터 내부의 속도 제어는 동작합니다. GPIO PWM 신호나 RC 서보 펄스 폭으로 위치를 명령하는 방식과 구분합니다.

- 모터를 고정하고 움직임 범위에 손이나 물체가 없는지 확인합니다.
- 진행자가 확인한 낮은 속도와 작은 상대 목표각도를 사용합니다. 예: 15°/s 상한, 상대 목표 +30°. 이 값은 모든 장비에 대한 안전 보장이 아니라 수업 설정 예시입니다.
- 속도 제한을 해제하는 `max`는 사용하지 않습니다. 시작·정지 명령과 전원 차단 위치를 먼저 확인합니다.
- 과제에서는 외부 ADC 배선, 외부 엔코더 연결, PWM 직접 구동, anti-windup 새 구현, micro-ROS 설치를 요구하지 않습니다.

## 문제 1. 목표를 보내고 움직임을 확인하세요

**연결: 1강 제어와 시스템 응답 + 5강 액추에이터 구동 / 25점**

### 할 일

1. OpenCR과 다이나믹셀의 연결 및 모터 ID를 확인하고 제공된 P 제어 예제를 실행하세요.
2. 진행자가 정한 작은 목표각도 한 개를 입력하고 약 5~10초간 로그를 관찰하세요. 움직임을 마치거나 이상이 있으면 정지하세요.
3. 목표각도와 현재각도가 보이는 로그 5행 이상을 저장하세요. 이 로그를 문제 2에서도 사용합니다.

수업 예제의 시작 명령 형식은 `s Kp 속도상한 상대목표각도`입니다. 진행자가 검증한 경우 `s 0.3 15 30`처럼 실행하고, 정지는 `x`를 사용합니다. 각 실행은 시작 위치를 0°로 잡으므로 다음 실행에서도 이동할 공간을 확인합니다.

### 답할 내용

- 사용한 모터 모델·ID와 입력한 목표각도·속도 상한을 적으세요.
- 기록에서 목표값, 측정값, OpenCR이 보내는 제어 출력이 각각 무엇인지 이름과 단위로 적으세요.
- 측정값이 목표에 가까워졌는지 실제 기록을 근거로 2문장 이내로 설명하세요.

**제출 증거:** 설정 1줄 + 로그 화면 1장 또는 CSV 1개. 동영상은 필요하지 않습니다.

**채점:** 설정·실행 확인 10점, 목표·측정·출력 구분 10점, 관찰 설명 5점.

## 문제 2. 측정값으로 오차를 설명하세요

**연결: 2강 피드백과 안정성 + 6강 센서 인터페이스 / 25점**

### 할 일

문제 1의 로그에서 초기·중간·마지막의 세 시점을 골라 아래 표를 채우세요. 새로운 실험은 필요하지 않습니다.

| 시점 또는 시간[s] | 목표각도[°] | 현재각도[°] | 오차 = 목표 - 현재[°] |
|---|---|---|---|
| 초기 | | | |
| 중간 | | | |
| 마지막 | | | |

### 답할 내용

- 세 시점의 오차를 계산하고, 오차의 절댓값이 대체로 줄었는지 한 문장으로 설명하세요.
- 현재각도를 얻는 센서는 무엇이며, OpenCR은 그 값을 어떤 경로로 읽는지 한 문장으로 설명하세요.
- 목표가 +30°인데 현재각도가 +35°라면 오차의 부호는 무엇인지, 오차만 사용하는 P 제어가 어느 방향의 보정을 요구하는지 적으세요.

이미 각도[°]로 변환된 로그를 사용해도 됩니다. 원시 엔코더 카운트 환산식 유도, 필터 구현, ADC 실습 재수행은 요구하지 않습니다. 통신 오류를 측정값 0으로 바꾸어 기록하지 않습니다.

**제출 증거:** 위 표 1개 + 짧은 답변. 문제 1의 로그를 재사용합니다.

**채점:** 오차 계산 10점, 센서·통신 경로 설명 10점, 보정 방향 설명 5점.

## 문제 3. P 게인 하나만 바꿔 비교하세요

**연결: 3강 PID와 튜닝 + 7강 목표값 추종 / 25점**

### 할 일

1. 제공된 P 제어 예제로 총 두 번 실행하세요. 첫 번째는 문제 1의 기록을 재사용해도 됩니다.
2. 두 번째 실행에서는 **Kp만** 진행자가 지정한 값으로 바꾸세요. 목표각도, 속도 상한, 부하, 측정 주기는 유지합니다. 예: 검증된 환경에서 Kp 0.3과 0.6 비교.
3. 두 실행의 시작 자세와 이동 여유를 맞추세요. 각 로그의 시작 시각을 0초로 보고, 같은 경과 시각(예: 5초)의 현재각도를 비교하세요.

| 실행 | Kp | 목표각도[°] | 속도 상한[°/s] | 같은 경과 시각[s] | 해당 시각의 현재각도[°] | 목표를 넘었나요? |
|---|---|---|---|---|---|---|
| A | | | | | | |
| B | | | | | | |

### 답할 내용

- 어느 설정이 해당 시각에 목표에 더 가까웠는지 설명하세요. 차이가 거의 없어도 관찰대로 적으면 됩니다.
- I항과 D항이 각각 무엇에 반응하는지 한 문장씩 적으세요. I·D를 실제로 튜닝하거나 별도 실행할 필요는 없습니다.
- 이 실험에서 바꾼 Kp가 OpenCR의 위치 제어 게인인지, 다이나믹셀 내부 게인 레지스터인지 구분하세요.

Kp가 크면 항상 더 좋다고 결론 내리지 않습니다. 속도 제한 때문에 두 응답이 비슷할 수 있습니다. 정착시간 계산, 최적 게인 탐색, Ziegler-Nichols 실험과 추가 그래프는 요구하지 않습니다.

**제출 증거:** 비교표 1개 + 두 실행의 로그. 총 두 번이면 충분합니다.

**채점:** 한 조건만 바꾼 비교 10점, 관찰에 근거한 해석 10점, I·D 및 게인 위치 설명 5점.

## 문제 4. 통신과 제어의 역할을 구분하세요

**연결: 4강 MCU·주변장치·타이머 + 8강 micro-ROS·ROS2 연동 / 25점**

### 할 일

아래는 **답안 작성을 위해 만든 설명용 통신 기록**입니다. 실제 실험 결과가 아닙니다. 이를 읽고 구조와 동작을 설명하세요. 이 문제는 새로 micro-ROS를 설치하거나 펌웨어를 포팅하지 않아도 풀 수 있습니다.

설명용 인터페이스: `/motor/target`은 목표각도[°], `/motor/state`는 현재각도[°]입니다. **8강 기존 속도 예제의 RPM 인터페이스와 구분합니다.** 여기서는 단순화를 위해 메시지 자료형·패키지 구현은 묻지 않습니다.

```text
제어 계산: OpenCR에서 10ms마다 실행
상태 발행: 100ms마다 실행
0.0s  PC: /motor/target에 30.0 발행
0.1s  PC: /motor/state에서 2.0 수신
0.5s  PC: /motor/state에서 12.0 수신
1.0s  PC: /motor/state에서 22.0 수신
2.0s  PC: /motor/state에서 29.0 수신
```

### 답할 내용

- `PC의 ROS2 노드`, `micro-ROS Agent`, `OpenCR`, `다이나믹셀`을 연결하고, 목표 전달과 측정값 반환의 방향을 화살표로 표시하세요.
- 목표를 보내는 쪽과 현재각도를 보내는 쪽을 각각 적으세요.
- 제어 계산 10ms와 상태 발행 100ms 중 무엇이 더 자주 실행되는지, 상태를 한 번 보내는 동안 제어 계산은 몇 번 실행되는지 적으세요.
- 통신이 끊겨도 로컬 제어가 계속될 수 있습니다. 이때 이전 명령을 계속 따르게 둘지 정지시킬지 왜 정책을 정해야 하는지 한 문장으로 설명하세요. 실제 통신 단절 실험은 하지 않습니다.

이미 수업에서 동작하는 연동 환경이 있다면, 진행자 시연이나 본인의 기존 기록으로 표를 대체해도 됩니다. 그 경우 사용한 단위가 각도인지 RPM인지 명시하세요. **설명용 기록을 분석한 제출물도 동일한 배점이며, 직접 연동을 구축했다는 증거로 취급하지 않습니다.**

**제출 증거:** 구조도 1개(손그림 가능) + 짧은 답변 4개. 패키지·bag·영상 제출은 필요하지 않습니다.

**채점:** 구조와 흐름 10점, 송수신 역할 5점, 주기 비교 5점, 통신 단절 정책 설명 5점.

## 제출 방법과 평가

`lv2_module1_이름.zip` 하나로 제출합니다.

```text
lv2_module1_이름.zip
├── 답안.pdf 또는 답안.md   # 문제 1~4, 표와 구조도 포함, 2쪽 이내 권장
└── results/               # 실행 A·B의 로그 또는 화면 캡처 2개
```

- 모델·ID·게인·목표각도·속도 상한과 사용한 예제 이름은 답안에 적습니다.
- 코드를 수정했다면 변경한 소스 파일만 추가합니다. 예제를 그대로 썼다면 파일명만 적어도 됩니다.
- 표와 로그가 일치하고 본인이 결과를 설명할 수 있는지를 평가합니다. 추가 기능이나 실험 횟수에 가산점은 없습니다.
- 목표에 완벽히 도달하지 못해도 설정·측정·해석이 명확하면 해당 항목을 평가합니다. 실패한 실험을 성공한 것처럼 바꾸지 않습니다.
- 장비 문제로 실행할 수 없다면 진행자에게 확인을 받고 제공 로그로 분석할 수 있습니다. 답안에 대체 자료 사용을 표시하고, 하지 않은 하드웨어 실행은 완료로 표시하지 않습니다.

## 진행자 메모

이 개정본의 채점은 위 4문제 합계 **100점**을 사용합니다. 기존 성취도 엑셀의 4점·5점 구현 기준을 그대로 충족하는 과제로 해석하지 않습니다. 특히 문제 4는 구조·기록 해석 평가이며 micro-ROS 구현 성취를 인증하지 않습니다.
